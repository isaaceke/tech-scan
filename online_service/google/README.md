The native app must use the actual HTTPS Cloud Run .run.app origin for uploads. Firebase Hosting's proxy has a 60-second timeout, so it is only the owner panel/API entry point. The release guard rejects a Hosting URL, a different infrastructure provider, an unconnected owner or a different destination. Owner sign-in happens through the Firebase-hosted panel. Direct Cloud Run browser sign-in is not enabled by the generated origin allowlist; the service's direct origin is for native API requests.

All client Firestore access is denied by firestore.rules. The Cloud Run service uses Application Default Credentials from its dedicated Google service account, not a downloaded private key. It needs roles/datastore.user for the configured database and roles/secretmanager.secretAccessor on only the encryption secret. Give the deployment identity separate deployment/build permissions; do not give them to the runtime service account. The public Cloud Run invoker endpoint exposes the API; application-level owner/operator authorization protects every account decision and upload.

Each API operation acquires a fenced Firestore lease. The lease renews during long operations and all storage reads/writes check its holder and expiry. An expired worker cannot commit or release a newer worker's lock. Outbound requests are aborted if the lease is lost or the operation exceeds nine minutes. A failed process may hold the lease for up to two minutes; phones retain PDFs and retry. No network call is performed inside a retried Firestore transaction. Permission changes and their audit events commit atomically. Delivery receipts, delivery journal and delivery audit commit atomically after SHA-256 readback. Retries create no additional verified receipt/audit event. Audit records are append-only through the application, with a hash chain; a privileged database administrator can alter storage. This is not a claim of regulatory compliance or immutable external retention.

Local verification uses Google's Firestore emulator and synthetic Microsoft accounts/endpoints. The HTTP test sends the real two-page PDF previously captured by the native camera, loses an upload response, restarts the HTTP service, retries the original scan, independently reads back its bytes and observes one receipt. It removes a synthetic approval and verifies rejection after another restart. Additional tests cover transaction rollback, token privacy, cookie authentication, cross-origin rejection, competing revisions, stale lease holders and slow-operation renewal. These tests do not approve any real account or establish a live staff sign-in.

Use Node 24 LTS. Install locked dependencies with npm ci. Start a local Firestore emulator on 127.0.0.1:8788 under the reserved project demo-enugu-scanner. Set FIRESTORE_EMULATOR_HOST=127.0.0.1:8788, then run npm run test:google. Run npm test for the shared API/audit suite and historical Cloudflare runtime regression. Test modules refuse to run against a real Firestore project. Production startup rejects emulator configuration when K_SERVICE is set. The Google container includes production dependencies only; the historical Wrangler/Miniflare tooling is excluded.
